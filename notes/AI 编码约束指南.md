量化交易开发与回测 AI 编码约束指南 (AI Coding Constraints)
本指南旨在规范量化交易系统（策略开发、回测引擎构建、数据处理）的 AI 编码行为。在生成任何相关代码时，请严格遵守以下架构准则、数据处理原则和回测纪律。
1. 架构与框架选型基准 (Framework Context)
在生成代码前，必须明确当前项目基于的底层框架，并采用相应的技术栈和性能优化策略：
场景 A：基于 VN.PY (VeighNa) / 中低频策略 (CTA / 套利)
语言限制：以 Python 为主，利用 NumPy/Pandas 优化向量化计算。
数据精度：默认处理 Tick (Level-1)、分钟 K 线或日线数据。
架构风格：严格遵循事件驱动机制（Event-Driven）。策略逻辑必须继承模板类，隔离数据层与业务层。
场景 B：基于 Spider (Spider-Trading) / 高频策略 (HFT / 做市)
语言限制：核心逻辑必须使用现代 C++ (C++14/17/20)，追求极致性能。
数据精度：必须处理 Level-2 极速行情、深序订单簿（Order Book）及逐笔成交/委托。
架构风格：禁止使用阻塞操作和锁（采用无锁队列），使用内存池、CPU 亲和性绑核、零拷贝（Zero-copy）技术。
2. 数据源接入与处理约束 (Data Processing Rules)
在编写数据下载、清洗和馈送代码时，必须防范“垃圾进，垃圾出”：
数据匹配性与成本感知：
低频/研究：优先接入免费开源接口（AkShare, Tushare）或中等成本 API（RQData, TqSdk）。
高频/L2：默认数据源为本地二进制文件（交易所快照/极速行情数据），需提供高效的 I/O 反序列化代码。
消除幸存者偏差：选股类策略的数据池代码中，必须包含退市股票逻辑，禁止硬编码当前的成分股列表。
除权除息处理：股票回测代码必须强制加入前复权（或动态复权因子）计算逻辑。
连续合约拼接：期货回测代码禁止直接拼接不同月份合约，必须实现“价差平移”或“收益率拼接”的换月逻辑。
3. 回测引擎与防作弊纪律 (Backtesting Execution Constraints)
【核心红线】禁止任何形式的未来函数 (Look-ahead Bias)。代码生成必须通过以下核查：
时序隔离法则：使用 Bar[T] 的收盘价/成交量计算指标并产生交易信号，订单必须在 Bar[T+1] 的开盘价或后续时点撮合成交。绝不允许在获取 Bar[T].Close 的瞬间以 Bar[T].Close 成交。
真实摩擦模拟 (Friction Models)：
强制滑点 (Slippage)：必须编写滑点模型（如买入价 + N 跳，卖出价 - N 跳）。
强制手续费 (Commission)：必须包含双边或单边手续费、印花税的计算扣除。
流动性与容量限制：代码必须检查 Volume，单笔生成订单的数量不得超过当前 Bar/Tick 真实市场成交量的设定比例（默认阈值：10%）。无成交量时（如涨跌停死板）禁止撮合成交。
4. 绩效评估指标强制输出 (Performance Evaluation Metrics)
在生成回测结果评估代码时，禁止仅输出“总收益率”。必须编写完整的统计模块，包含并打印以下四类核心指标：
风险维度：
最大回撤 (Max Drawdown - 金额及百分比)
最长回撤恢复期 (Max Drawdown Duration)
收益风险比：
夏普比率 (Sharpe Ratio - 无风险利率需设为动态或合理常量)
卡玛比率 (Calmar Ratio = 年化收益 / 最大回撤)
交易特征：
胜率 (Win Rate)
盈亏比 (Profit / Loss Ratio)
交易总次数 (Total Trades)
成本敏感度：
单笔平均净利润 (Net Profit per Trade)
5. 策略验证与反过度拟合协议 (Anti-Overfitting Protocol)
在生成策略参数优化（Parameter Optimization）相关的代码时：
强制样本外测试 (OOS)：优化代码必须将数据集分割。禁止将所有数据传入优化器。标准的实现应是：Train Set（如前70%时间）用于网格搜索/遗传算法找寻最优参数，Test Set（后30%时间）用于盲测记录。
参数平原评估：在生成 3D 绩效图或热力图代码时，提示开发者寻找“参数平原”而非单一极值的“孤峰”。
代码逻辑：如果策略规则中出现针对特定历史事件（如特定日期硬编码）的特异性判定，将被视为过度拟合代码，需触发警告并重构。
