# 01-prd-sense.md -- VeighNa (vnpy)

本文件定义产品核心理念与判断准则，AI Agent 在功能迭代时应以此为决策依据。

---

## 产品定位

VeighNa 是面向专业量化交易员的开源 Python 量化交易系统开发框架，运行于 Windows / Linux / macOS，通过事件驱动引擎统一接入国内外多市场交易接口，并提供策略引擎、数据管理、AI 因子研究等一体化开发能力。

## 产品愿景

成为量化交易员首选的开源基础设施，让专业交易员以最低成本构建、部署和迭代自己的量化交易系统。

---

## 核心用户

| 角色 | 诉求 | 优先级 |
|------|------|--------|
| 量化策略开发者 | 快速接入多市场行情和交易，专注策略逻辑实现 | P0 |
| AI 量化研究员 | 高效进行多因子特征工程、模型训练、策略回测 | P1 |
| 私募基金/量化团队 | 稳定可靠的实盘交易基础设施，支持多策略并行运行 | P0 |
| 量化框架贡献者 | 易于扩展的接口设计，方便开发新 Gateway / App | P1 |

---

## 体验原则

- 专业性优先：为有经验的量化交易员设计，不做过度简化
- 模块化扩展：Gateway / App / Database / DataFeed 均可插拔替换，不侵入核心
- 稳定性至上：实盘交易场景不引入未经验证的依赖，核心模块变更需充分测试
- 透明可控：所有数据流通过 EventEngine 可观测，策略行为可追溯
- 开放生态：社区可自由发布 vnpy_xxx 扩展包，主仓库保持轻量核心

---

## 产品判断准则

按优先级排序：

1. 实盘交易稳定性：任何变更不得引入影响实盘委托/成交可靠性的风险
2. 框架接口兼容性：对外公开的 BaseGateway / BaseApp / BaseEngine / 数据对象接口，向后兼容变更优先
3. 开发体验：提供清晰的类型注解和文档，降低二次开发门槛
4. 功能完整性：优先保障核心交易功能完整，新功能以插件 App 形式扩展

优先级低的功能需求，哪怕技术可行，也应推迟实现或以独立 App 包形式发布。

---

## 不做什么

- 不提供面向散户的一键炒股/跟单 SaaS 服务
- 核心仓库不集成特定交易所专有 API 或数据服务的具体实现（以 vnpy_xxx 包独立发布）
- 不做 Web 前端管理系统（web_trader 提供最基础的 B-S 接口，不做完整 SaaS）
- 不将 AI 生成的交易信号直接路由到实盘（研究模块与实盘解耦，不自动下单）
